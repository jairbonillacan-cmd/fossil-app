# ADR-0001: Tauri 2 como shell nativo

- **Estado:** aceptado · **Fecha:** 2026-10-13 · **Área:** `area:infra`

## Contexto
Necesitamos una app nativa de Windows, ligera (< 200 MB de RAM en reposo, instalador < 30 MB) y con acceso al sistema: atajos globales, toasts, OCR y credenciales. Las apps de escritorio hechas con Electron cargan un Chromium completo y pesan mucho más.

## Decisión
**Tauri 2**, con el backend en Rust y la UI en WebView2 (incluido en Windows 10/11).
- Plugins oficiales: global-shortcut, notification, deep-link, updater, single-instance, window-state.
- Efecto Mica vía `window-vibrancy`.

## Consecuencias
- El bundle y la RAM son varias veces menores que con Electron, y la lógica pesada vive en Rust.
- Hay una sola WebView: no se embebe Chromium. Las diferencias entre motores no importan porque solo apuntamos a Windows.
- Los agentes tienen que escribir Rust. Los tipos se comparten con tauri-specta para reducir errores.

## Alternativas consideradas
- **Electron:** rápido de desarrollar, pero pesado; contradice el principio de ser ligera.
- **WinUI 3 / .NET:** muy nativo, pero su ecosistema de editores ricos y de vistas de base de datos (tabla, tablero) es pobre frente al de la web.
- **Flutter:** el editor de texto enriquecido y los CRDT están menos maduros.
